# RuoJingo-45

A 2D serious game that teaches networking fundamentals to 2nd-year IT students, using a Duolingo-style
microlearning loop: skill-tree map, short lessons, instant grading, hearts, XP, a daily streak and spaced
repetition of missed questions. It is a stepping stone before Cisco Packet Tracer.

This repository is a **playable vertical-slice prototype** (capstone research). Correctness and clarity of
the content and systems come first; all art is placeholder (Unity UI primitives + built-in sprites).

---

## Requirements

- **Unity 2022.3 LTS** (the project was authored against 2022.3.20f1; any 2022.3.x patch works; Unity Hub
  will offer to switch the version, accept it).
- Packages (resolved automatically from `Packages/manifest.json`): uGUI, TextMeshPro 3.0.6,
  Test Framework, Universal RP, 2D Sprite.
- No backend and no paid assets.

## Open the project

1. Clone the repository.
2. Unity Hub > **Add** > **Add project from disk** > select the repository folder (the one containing
   `Assets/`, `Packages/`, `ProjectSettings/`).
3. Open it. The first import takes a few minutes (Unity generates `Library/`, `.meta` files and the
   default ProjectSettings). There should be **no compile errors** in the Console.

## Build the scenes (one menu click)

Scenes, canvases and exercise prefabs are **generated by code**. Nothing is set up by hand.

1. Menu **Tools > RuoJingo > Build Prototype Scenes**.
2. The first time, the builder imports the *TMP Essential Resources* (fonts and settings) and then continues
   automatically. If a dialog says they are missing instead, run
   **Window > TextMeshPro > Import TMP Essential Resources** and click the menu item again.
3. Result:
   - `Assets/Scenes/MainMenu.unity`, `SkillTree.unity`, `Lesson.unity`, `Results.unity`
   - `Assets/Prefabs/Exercises/*.prefab` (one per exercise type)
   - All four scenes are added to **File > Build Settings** (MainMenu first).
   - `MainMenu` is opened.

Re-running the menu item overwrites the generated scenes and prefabs, so make layout changes in
`Assets/Editor/PrototypeBuilder.cs`, not by hand. If you want to hand-tune instead, stop re-running it.

Batch mode alternative:
`Unity -batchmode -quit -projectPath . -executeMethod RuoJingo.PrototypeBuilder.BuildAll`
(run it once interactively first so the TMP resources get imported).

## Play in the Editor

1. Open `Assets/Scenes/MainMenu.unity` and press **Play**.
2. Set the Game view to a portrait resolution (e.g. *1080x1920*) or 16:9. Both work: the UI is a
   1080-wide portrait column that is centred on wide screens.

Any scene can also be played directly (the `GameState` singleton creates itself), but start from MainMenu
for the full flow.

### Walkthrough for the "done" criteria

1. **MainMenu**: shows streak, total XP and hearts. Press **PLAY**.
2. **SkillTree**: Unit 1 is green, Units 2-3 are grey (locked). The mock leaderboard is at the bottom.
3. Tap **Unit 1** and answer the 8 exercises. *Deliberately miss one* (e.g. the Layer 3 question) so it
   enters the spaced-repetition system. Keep at least 1 heart.
4. **Results**: XP earned, accuracy, hearts left, "Unit 2 unlocked!". Press **CONTINUE**.
5. On the SkillTree, Unit 1 is gold (passed) and Unit 2 is green. Tap **Unit 2**: it contains two
   **WireOrder** exercises (T568B and T568A), plus the missed Unit 1 question, labelled
   **"REVIEW - from Unit 1"** in the header.
6. Finish it and see Results with XP.
7. Stop Play mode and press Play again (or quit and relaunch a build): XP, streak, unlocked units, hearts
   from the last lesson and the review queue are all restored from the save file.
8. Lose 5 hearts in any lesson to see the **"Out of hearts! Review and try again"** screen, which lists
   each missed question with its correct answer.

Dev helpers: **Tools > RuoJingo > Delete Save File** (start fresh) and **Tools > RuoJingo > Show Save Folder**.

## Run the unit tests

**Window > General > Test Runner > EditMode > Run All.**

Tests live in `Assets/Tests/EditMode` (assembly `RuoJingo.Tests.EditMode`):

| File | Covers |
|---|---|
| `HeartSystemTests` | 5 hearts, lose 1 per wrong answer, empty at 0, never negative |
| `StreakSystemTests` | same-day, next-day, missed-day reset, month boundary |
| `SpacedRepetitionTests` | Leitner boxes 1-3, graduation, due logic, max 2 reviews from earlier units, a missed question reappearing in the next lesson |
| `SubnetMathTests` | hosts = 2^(32-prefix) - 2 for /24-/30, masks, smallest prefix for N hosts, subnet count |
| `LessonFlowTests` | XP rules, pass -> unlock + streak, 0 hearts -> fail with no XP, 10-exercise cap, cable rule, wire orders, answer normalisation, mock leaderboard |
| `ContentFileTests` | every shipped lesson JSON validates, 3 units with at least 6 questions, unique ids, subnet answers agree with the formula |

## Build a player

**File > Build Settings**, pick a platform, then **Build**. The scenes are already in the list.

- **Windows**: *Windows, Mac, Linux* > Target *Windows*. Any resolution works; for a phone-like window
  set *Player Settings > Resolution* to windowed 1080x1920 or 540x960.
- **WebGL**: switch platform to *WebGL* and build. Serve the output folder from a local web server
  (e.g. `python -m http.server` inside the build folder), because browsers block `file://` loading.
  Lessons are read from StreamingAssets with `UnityWebRequest`. Saves go to the browser's IndexedDB
  through `Application.persistentDataPath`. Windows is the primary tested target.

Save file location: `Application.persistentDataPath/ruojingo_save.json`
(Windows: `%USERPROFILE%\AppData\LocalLow\<CompanyName>\<ProductName>\`).

## Project layout

```
Assets/
  Editor/PrototypeBuilder.cs        menu item that generates scenes/prefabs and Build Settings
  Scripts/
    Core/      pure C# game rules (no MonoBehaviours except GameState / SaveSystem)
      HeartSystem, XpSystem, StreakSystem, SpacedRepetition, LessonRunner, ProgressService,
      LeaderboardMock, SubnetMath, WireStandards, AnswerChecker, ContentValidator, SaveSystem, GameState
    Data/      LessonData (JSON schema), SaveData, ContentRepository (StreamingAssets loader)
    Exercises/ IExercise, ExerciseView base, one view per exercise type, wire visuals
    UI/        one small controller per screen + theme colours
  StreamingAssets/lessons/          index.json + one JSON file per unit
  Tests/EditMode/                   NUnit EditMode tests
```

All code is in namespace `RuoJingo`. Assemblies: `RuoJingo` (runtime), `RuoJingo.Editor`,
`RuoJingo.Tests.EditMode`.

### Game rules as implemented

| System | Rule |
|---|---|
| Hearts | 5 at the start of every lesson; -1 per wrong answer; at 0 the lesson ends with "Review and try again". The menu shows hearts left after the last lesson. |
| XP | +10 per correct answer, +20 bonus for a perfect lesson. Only awarded when the lesson is passed. |
| Pass | Finish every exercise with at least 1 heart. Passing Unit N unlocks Unit N+1. |
| Streak | +1 when you complete a lesson on the day after your last completed lesson; unchanged for more lessons on the same day; resets to 0 (shown) / 1 (on the next lesson) after a missed calendar day. Uses the device's local date. |
| Spaced repetition | Leitner, 3 boxes. Clock = lessons started. Wrong -> box 1 (due next lesson). Correct while tracked -> up one box (due in 2, then 4 lessons). Correct in box 3 -> graduated. Each lesson mixes in up to 2 due questions from *earlier* units, never as the first exercise. Lesson length is capped at 10. |
| Leaderboard | **Mock.** Player + 5 hard-coded classmates (names end in "(mock)"), sorted by this week's XP, labelled "MOCK DATA". |

### Adding or editing content

Lessons are data, not code. Add a file to `Assets/StreamingAssets/lessons/`, list it in `index.json`, and
use one of these exercise shapes (all fields are on `ExerciseData`):

```jsonc
{ "id": "u4_q1", "type": "MultipleChoice", "prompt": "...", "options": ["A","B"], "correctIndex": 0, "explanation": "..." }
{ "id": "u4_q2", "type": "WireOrder",      "prompt": "...", "correctOrder": ["white/orange", "...8 wires"] }
{ "id": "u4_q3", "type": "DeviceMatch",    "prompt": "...", "pairLeft": ["Hub","Switch"], "pairRight": ["Layer 1","Layer 2"] }
{ "id": "u4_q4", "type": "NumericInput",   "prompt": "...", "acceptedAnswers": ["255.255.255.192"], "hint": "dotted decimal" }
{ "id": "u4_q5", "type": "CableTypeChoice","prompt": "...", "endA": "T568A", "endB": "T568B" }
```

Ids must be globally unique (they key the spaced-repetition state). `ContentValidator` rejects malformed
exercises at load time (logged as errors) and in `ContentFileTests`; WireOrder answers must exactly match
T568A or T568B, and the CableTypeChoice answer is derived from the two standards, so it cannot be mistyped.
Use ASCII text: the default TMP font has no arrows or symbols.

### Swapping art later

- Colours: `Assets/Scripts/UI/UiTheme.cs` and `Assets/Scripts/Exercises/WireColors.cs`.
- Sprites: the builder uses Unity's built-in `UISprite`, `Knob` and `InputFieldBackground`; change them in
  `PrototypeBuilder.LoadSharedAssets()` or replace the `Image.sprite` on the generated prefabs/scenes.
- Layout: `PrototypeBuilder.cs` (one method per screen / prefab).

## Known limitations / stubs

- Placeholder art only; no audio or animations.
- The leaderboard is local mock data; there is no account system or backend.
- Each unit is a single fixed lesson (its 8 exercises, plus reviews). There are no multiple lessons per unit
  and no question pools yet.
- The streak uses the device clock; there is no anti-tamper protection.
- UI input uses the classic Input Manager (`StandaloneInputModule`). If you switch the project to the new
  Input System only, replace the EventSystem module with `InputSystemUIInputModule`.
- URP is in the manifest (per the URP 2D template) but no pipeline asset is assigned; the game is pure
  Screen Space Overlay UI, so it renders the same either way. To use it, create
  *Assets > Create > Rendering > URP Asset (with 2D Renderer)* and assign it in *Project Settings > Graphics*.
